## 1. RUST/WASM SDK CORE (/crates/cveil-sdk-core/)

### Key Data Structures

MaskingType Enum (src/models/types.rs:112-152):
- Plaintext = 0        → Return unchanged
- RedactUpToLast4 = 1  → "****5678" (last 4 visible)
- RedactLocal = 2      → "****@example.com" (email domain visible)
- Hash256 = 3          → SHA256 hex digest
- RedactAll = 4        → "***" | 0 | null (type-safe default)

Ordered by restrictiveness: Plaintext < RedactAll
Uses Ord for max(a,b) → most restrictive wins

PolicyType Enum:
- Field    → Policy for specific field (e.g., "User/email")
- Category → Policy for category (e.g., "PII")

PurposeRegulationLink (KEY DATA STRUCTURE):
  - on_granted:  MaskingType  (default: Plaintext)
  - on_denied:   MaskingType  (default: RedactAll)
  ↳ Each purpose→regulation edge defines masking based on consent

### Core Masking Functions (src/masking/engine.rs)

apply_mask(value: Value, type: MaskingType) → Value
- Applies single masking strategy to JSON value
- Input: any JSON type + MaskingType
- Output: masked value (type-safe sentinels)

mask_json_tree(value_mut, resolutions: HashMap<path, MaskingType>)
- Tree walker for nested JSON
- DFS traversal of objects/arrays
- Exact path match → mask immediately, don't recurse
- No match → recurse into children
- Example paths: "email", "address.street", "users.email"

### Evaluator (src/evaluator/consent_evaluator.rs)

evaluate_field(subject, entity, field_path, purpose, jurisdiction, now_ms) 
→ EvalResult::Resolved | EvalResult::NeedsFetch

PROCESS:
1. Build policy names:
   - Field-level:    "FIELD:{entity}/{field}:{purpose}"
   - Category-level: "CAT:{category}:{purpose}" (for all categories of field)
   
2. Check decision cache (field → categories precedence):
   - Look up subject→policy consent decision
   - Key: cache_key(subject, policy_name)
   
3. If cache hit:
   - Consent status (granted/revoked) → call resolve_masking_for_field()
   
4. If cache miss:
   - If conservative_fallback=true: resolve with consent_granted=false
   - Otherwise: return NeedsFetch (facade should call API)

KEY: Field policy decisions override category policies

### GraphStore (src/graph/store.rs)

resolve_masking_for_field(purpose, jurisdiction, consent_granted) → MaskingResolution

ALGORITHM:
1. Get regulations linked to purpose
2. Filter by jurisdiction (only active in target jurisdiction)
3. For each applicable regulation:
   - Extract on_granted OR on_denied based on consent_granted
   - Track most restrictive MaskingType
4. Return: { masking_type, regulation_name, lawful_basis }

KEY: Most restrictive masking type wins across regulations

### FFI Exports (src/ffi/exports.rs)

cveil_init(config_json) 
→ Initializes SDK state with SdkConfig

cveil_mask(subject, entity, json_payload, purpose) → {"data": value, "needsFetch": []}
→ CORE MASKING FUNCTION
1. Parse JSON
2. Discover registered fields for entity
3. Evaluate each field (ConsentEvaluator::evaluate_fields)
4. Build resolutions map + collect NeedsFetch items
5. Apply masking (mask_json_tree)
6. Return masked data + fetch signals

cveil_mask_with_jurisdiction(subject, entity, payload, purpose, jurisdiction)
→ Same as cveil_mask with explicit jurisdiction

cveil_mask_batch(subject, entity, json_array, purpose)
→ Masks array of objects

cveil_evaluate(subject, entity, fields_json, purpose)
→ Evaluate consent WITHOUT masking
→ Returns: [{ field, masking_type, needs_fetch, policy_names }]

cveil_ingest_graph_page(page_json)
→ Ingests paginated consent graph

cveil_ingest_decisions(subject, decisions_json)
→ Ingests consent decisions for subject

cveil_process_invalidation(event_json)
→ Processes SSE cache invalidation

## 2. JS SDK WRAPPER (/sdks/cveil-sdk-js/)

### Architecture
TypeScript facade over Rust WASM via Node.js WASI
- WasmBridge: Low-level memory I/O (string marshalling)
- CveilClient: High-level async API

### File Structure
src/
├── index.ts              # Main export
├── types.ts              # All TS interfaces
├── client.ts             # CveilClient class (main API)
├── wasm-bridge.ts        # WasmBridge (WASM FFI)
└── tests/

wasm/
└── cveil_sdk_core.wasm   # Compiled Rust (433KB)

### Core Types (src/types.ts)

CveilConfig:
  apiBaseUrl: string
  apiToken: string                   # Must start with "cveil_"
  defaultJurisdiction: string
  staleMode?: "apiFallback" | "conservativeMask"
  disconnectThresholdMs?: number     # Default: 60000
  decisionCacheMaxSize?: number      # Default: 10000
  decisionCacheTtlMs?: number        # Default: 300000
  dedupWindowSize?: number           # Default: 500

MaskResult:
  data: Record<string, unknown>      # Masked JSON
  needsFetch: NeedsFetchEntry[]      # Fields needing API fetch

NeedsFetchEntry:
  fieldPath: string                  # "email", "address.street"
  policyNames: string[]              # ["FIELD:User/email:Marketing"]

EvaluateResult:
  field: string
  masking_type: string
  consent_action?: string            # "GRANT", "REVOKE"
  needs_fetch: boolean
  policy_names?: string[]

DecisionEntry (for ingest):
  policyName: string
  action: "GRANT" | "REVOKE" | "EXPIRE"
  expiresAt?: number | null          # Unix milliseconds

### WasmBridge (src/wasm-bridge.ts)

load(wasmPath): Promise<WasmBridge>
- Loads WASM module + initializes WASI
- Returns bridge instance

call0/call1/call2/call4/call5(fn, ...args): string
- Calls WASM function with 0-5 string arguments
- Marshalling:
  1. Encode args to UTF-8 bytes
  2. Allocate WASM memory (cveil_alloc)
  3. Copy bytes to WASM memory
  4. Call WASM function
  5. Read result (ptr + len)
  6. Deallocate memory
  7. Throw CveilWasmError if rc ≠ 0

### CveilClient (src/client.ts)

create(options): Promise<CveilClient>
- Loads WASM module
- Initializes with cveil_init(config)
- Loads full consent graph (paginated)
- Connects SSE (if autoConnect)

MAIN METHODS:

mask(subject, entity, data, purpose): Promise<MaskResult>
1. Call WASM: cveil_mask(...)
2. If needsFetch.length > 0:
   a. Fetch decisions: POST /api/v1/subjects/{subject}/evaluate
   b. Ingest: cveil_ingest_decisions(subject, decisions)
   c. Retry mask call
3. Return masked data

maskWithJurisdiction(subject, entity, data, purpose, jurisdiction)
- Same as mask but with jurisdiction override

maskBatch(subject, entity, data: [], purpose)
- Masks array of objects

evaluate(subject, entity, fields: [], purpose): EvaluateResult[]
- Evaluate without masking

ingestDecisions(subject, decisions: DecisionEntry[])
- Manually ingest decisions

loadGraph()
- Fetches full graph via paginated API
- Ingests into WASM

connectSSE()
- Establishes SSE connection to /api/v1/events/subscribe
- Listens for invalidation messages
- Auto-reconnects with exponential backoff (1s → 30s)
- Calls cveil_process_invalidation() per event

status(): SdkStatus
- Returns: { initialized, connectionState, graphNodes, cachedDecisions }

## 5. MASKING CONFIGURATION & GOVERNANCE POLICIES

### Policy Types: FIELD vs CATEGORY

FIELD Policy:
  Pattern:   "FIELD:{entity}/{field}:{purpose}"
  Example:   "FIELD:User/email:Marketing"
  Meaning:   Specific consent rule for exact field
  Precedence: FIRST (overrides category)

CATEGORY Policy:
  Pattern:   "CAT:{category}:{purpose}"
  Example:   "CAT:PII:Marketing"
  Meaning:   Blanket rule for all fields tagged with category
  Precedence: SECOND (fallback)

Evaluation Order (ConsentEvaluator, lines 54-84):
1. Check FIELD:{entity/field}:{purpose} decision
   ├─ Found → use this
   └─ Not found → continue
2. Check all CAT:{category}:{purpose} (for all categories of field)
   ├─ Found (any) → use this
   └─ Not found → NeedsFetch or conservative default

### How Masking Relates to Governance

Consent Scope (field/category + purpose)
    ↓
Policy {policyType: FIELD|CATEGORY}
    ↓
Subject Consent Decision {action: GRANT|REVOKE, expiresAt}
    ↓
Purpose → Regulation Link {on_granted: MaskingType, on_denied: MaskingType}
    ↓
resolve_masking_for_field() selects on_granted OR on_denied
    ↓
apply_mask() applies MaskingType to JSON value
    ↓
Masked JSON

EXAMPLE:
Purpose: "Marketing"
├─ Regulation: "GDPR" (active in EU)
│  ├─ onGranted: Plaintext
│  └─ onDenied: RedactAll
└─ Regulation: "CCPA" (active in California)
   ├─ onGranted: Plaintext
   └─ onDenied: RedactUpToLast4

For user@example.com, jurisdiction=EU:
- GRANT for email → Plaintext → show full email
- REVOKE for email → RedactAll → mask completely

### Stale Mode Behavior

ConservativeMask (default):
  When SSE disconnected > disconnectThresholdMs:
  ├─ cache hit → use cached decision
  └─ cache miss → apply onDenied (deny-by-default, NO API call)

ApiFallback:
  When SSE disconnected > disconnectThresholdMs:
  ├─ cache hit → use cached decision
  └─ cache miss → trigger NeedsFetch (facade calls API)

## 6. DATA FLOW: How Everything Connects

App HTTP Request
    ↓
CveilClient.mask(subject, entity, data, purpose)
    ↓
WasmBridge.call4(cveil_mask, ...)  [marshals JSON strings]
    ↓
WASM: cveil_mask()
    ├─ GraphStore: find registered fields
    ├─ ConsentEvaluator: evaluate_fields()
    │  ├─ DecisionCache: check subject→policy decisions
    │  └─ GraphStore: resolve_masking_for_field()
    │     ├─ purpose → regulations (filtered by jurisdiction)
    │     ├─ on_granted/on_denied by consent status
    │     └─ most restrictive wins
    ├─ Masking Engine: mask_json_tree()
    │  └─ apply_mask() per field
    └─ Return: {data, needsFetch}
    ↓
If needsFetch.length > 0:
  ├─ CveilClient: fetch POST /subjects/{subject}/evaluate
  ├─ WASM: cveil_ingest_decisions()
  └─ Retry mask()
    ↓
Return masked JSON to app
