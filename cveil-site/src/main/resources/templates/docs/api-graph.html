Consent Graph API

Query the consent topology graph and subscribe to real-time cache invalidation events via Server-Sent Events.

Authentication: Requires Bearer token with consent:graph:read permission.

Endpoint Overview

Method Endpoint Description
GET /api/v1/consent/graph Retrieve paginated consent topology graph
GET /api/v1/consent/events SSE stream of cache invalidation events

Graph Node Types

The consent graph models the relationships between all entities in your consent topology. Each node has a type and a unique name within that type.

Node Type Description
PURPOSE A reason for processing data (e.g. marketing_emails, analytics)
REGULATION A legal framework governing data processing (e.g. GDPR, CCPA)
JURISDICTION A geographic region where regulations apply (e.g. EU, California)
CATEGORY A classification of data (e.g. PII, financial, health)
FIELD A specific data field belonging to an entity (e.g. email, phone_number)
ENTITY A data entity or table in your system (e.g. users, orders)
SUBJECT A data subject whose consent is being managed
POLICY A consent policy linking purposes, categories, and regulations

Edges represent the relationships between nodes. For example, a PURPOSE node may be connected to a REGULATION node via an edge with a lawfulBasis property, indicating the legal basis for processing data under that purpose.

Endpoints

GET /api/v1/consent/graph

Retrieve the consent topology graph with cursor-based pagination. Use query parameters to filter by node type, name, or traversal depth.

Query Parameters

Parameter Type Default Description
cursor string — Pagination cursor from a previous response
limit integer 100 Number of results per page (1–1000)
rootType string — Filter by root node type (e.g. PURPOSE, REGULATION)
rootName string — Filter by root node name
depth integer — Maximum traversal depth from root nodes

Response 200

{
  "nodes": [
    {
      "type": "PURPOSE",
      "name": "marketing_emails",
      "properties": {
        "description": "Send promotional email campaigns"
      }
    },
    {
      "type": "REGULATION",
      "name": "GDPR",
      "properties": {
        "description": "General Data Protection Regulation"
      }
    }
  ],
  "edges": [
    {
      "sourceType": "PURPOSE",
      "sourceName": "marketing_emails",
      "targetType": "REGULATION",
      "targetName": "GDPR",
      "properties": {
        "lawfulBasis": "consent"
      }
    }
  ],
  "pageInfo": {
    "nextCursor": "abc123",
    "hasMore": true,
    "totalNodes": 42,
    "totalEdges": 38
  }
}

Cursor Pagination

The graph endpoint uses cursor-based pagination. To fetch subsequent pages, pass the nextCursor value from the pageInfo object as the cursor query parameter. When hasMore is false, you have reached the end of the result set.

GET /api/v1/consent/graph?cursor=abc123&limit=50

GET /api/v1/consent/events

Open a Server-Sent Events (SSE) stream that emits cache invalidation events in real time. SDKs use this endpoint to keep their local consent caches synchronized without polling.

Content Type

text/event-stream

Event Format

data: {"action":"GRANTED","subjectId":"user-123","scope":{"purposeName":"marketing"}}

Event Actions

Action Description
GRANTED A consent was granted
REVOKED A consent was revoked
ALL_REVOKED All consents for a subject were revoked
CATEGORY_CHANGED A data category was modified
FIELD_REMOVED A field was removed from an entity
FIELD_CHANGED A field's metadata was updated
ENTITY_REMOVED An entity was removed from the catalogue
ENTITY_CHANGED An entity's metadata was updated
PURPOSE_CHANGED A purpose definition was modified
REGULATION_CHANGED A regulation definition was modified
JURISDICTION_CHANGED A jurisdiction was modified
CONSENT_ENTRY_CHANGED A consent ledger entry was modified
POLICY_CHANGED A consent policy was modified
SUBJECT_CHANGED A subject's metadata was modified

SDK Integration

The Java and JavaScript SDKs automatically connect to the SSE events endpoint to maintain a local cache of the consent graph. When an invalidation event is received, the affected cache entries are evicted and re-fetched on the next evaluation call. This means your application always has near-real-time consent decisions without polling overhead.

If the SSE connection is interrupted, SDKs will automatically reconnect with exponential backoff. During reconnection, consent evaluations fall back to direct API calls.

// Java SDK — graph events are handled automatically
CveilClient client = CveilClient.builder()
    .apiKey("your-api-key")
    .enableRealtimeSync(true)  // enables SSE event stream
    .build();

// JavaScript SDK
const client = new CveilClient({
  apiKey: 'your-api-key',
  realtime: true  // enables SSE event stream
});
