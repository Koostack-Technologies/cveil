Webhooks API

Deliver real-time event notifications to your application when consent changes, DSAR requests progress, or other events occur.

Base path: /api/v1/webhooks/endpoints

Authentication: Bearer token with appropriate permissions.

Endpoint Summary

GET /api/v1/webhooks/endpoints List webhook endpoints
POST /api/v1/webhooks/endpoints Create webhook endpoint
PUT /api/v1/webhooks/endpoints/\{endpointId} Update endpoint
DELETE /api/v1/webhooks/endpoints/\{endpointId} Delete endpoint
GET /api/v1/webhooks/endpoints/\{endpointId}/deliveries List delivery attempts
POST /api/v1/webhooks/endpoints/\{endpointId}/test Send test event
POST /api/v1/webhooks/endpoints/\{endpointId}/rotate-secret Rotate signing secret

Endpoint Management

GET /api/v1/webhooks/endpoints

Lists all webhook endpoints configured for the tenant.

Response

[
  {
    "endpointId": "uuid",
    "url": "https://example.com/webhook",
    "events": ["consent.granted", "consent.revoked", "dsar.submitted"],
    "status": "active",
    "createdAt": "..."
  }
]

POST /api/v1/webhooks/endpoints

Creates a new webhook endpoint. Specify the URL, event types to subscribe to, and an optional signing secret.

Request

{
  "url": "https://example.com/webhook",
  "events": ["consent.granted", "consent.revoked"],
  "secret": "whsec_..."
}

Response

Endpoint object with generated endpointId.

PUT /api/v1/webhooks/endpoints/\{endpointId}

Updates an existing webhook endpoint's URL or subscribed events.

Request

{
  "url": "https://example.com/new-webhook",
  "events": ["consent.granted"]
}

DELETE /api/v1/webhooks/endpoints/\{endpointId}

Permanently deletes a webhook endpoint and stops all future deliveries to it.

Delivery & Testing

GET /api/v1/webhooks/endpoints/\{endpointId}/deliveries

Lists delivery attempts for a specific endpoint. Use query parameters to filter and paginate results.

Query Parameters

limit integer — Maximum results to return
offset integer — Number of results to skip
status string — Filter by delivery status

Response

[
  {
    "deliveryId": "uuid",
    "eventType": "consent.granted",
    "status": "delivered",
    "httpStatus": 200,
    "attemptCount": 1,
    "deliveredAt": "..."
  }
]

POST /api/v1/webhooks/endpoints/\{endpointId}/test

Sends a test event to the endpoint to verify connectivity and signature validation. Returns the delivery result.

POST /api/v1/webhooks/endpoints/\{endpointId}/rotate-secret

Rotates the signing secret for the endpoint. Returns the endpoint with the new secret. Update your verification logic before the old secret expires.

Webhook Verification

Cveil signs every webhook delivery with HMAC-SHA256 so you can verify that payloads are authentic. The signature is sent in the Cveil-Signature header along with a Cveil-Timestamp header.

Verification Steps

  1. Extract the Cveil-Timestamp and Cveil-Signature headers from the request.
  2. Concatenate the timestamp, a literal . character, and the raw request body.
  3. Compute HMAC-SHA256 using your webhook secret as the key.
  4. Compare the computed signature with the value in the header using a constant-time comparison.

Signature Formula

signature = HMAC-SHA256(webhook_secret, timestamp + "." + body)

Compare with Cveil-Signature header using constant-time comparison.
Tip: Reject requests where the timestamp is more than 5 minutes old to prevent replay attacks.

Retry Policy

When a delivery fails (non-2xx response or timeout), Cveil retries with exponential backoff:

Attempt 1 Immediate
Attempt 2 After 1 second
Attempt 3 After 2 seconds
Attempt 4 After 4 seconds
Attempt 5 After 8 seconds
... Continues doubling up to maximum interval

After all retry attempts are exhausted, the event is moved to a dead-letter queue. Failed deliveries can be inspected and replayed via the deliveries endpoint.

Note: Your endpoint must respond within 30 seconds. Responses with HTTP status codes 2xx are considered successful. All other status codes trigger a retry.
