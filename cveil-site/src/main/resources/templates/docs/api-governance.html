Governance API

Manage the legal framework — purposes, regulations, jurisdictions, and the policies that connect them to your data catalogue.

Authentication: Bearer token with appropriate permissions.

The Governance API defines why and where data processing is allowed. The hierarchy works as follows:

  • Regulations — legal frameworks such as GDPR or CCPA.
  • Jurisdictions — geographic regions where regulations are enforced (e.g. EU, California).
  • Purposes — reasons data is processed (e.g. marketing_emails). Each purpose is linked to regulations with a lawful basis and consent behaviour.
  • Policies — rules attached to a purpose that target either a category (all fields in that category) or a specific field.

When consent is evaluated, Cveil walks this graph: purpose → policies → catalogue items, applying the regulation's onGranted / onDenied transforms.

Endpoint Summary

Purposes

Method Endpoint Description
GET /api/v1/governance/purposes List all purposes
GET /api/v1/governance/purposes/\{purposeName} Get purpose details

Purpose Endpoints

GET /api/v1/governance/purposes

List all purposes with their linked regulations and policies.

Response 200

[
  {
    "purposeId": "uuid",
    "purposeName": "marketing_emails",
    "description": "Send promotional emails",
    "regulations": [
      {
        "regulationName": "GDPR",
        "lawfulBasis": "consent",
        "onGranted": "Plaintext",
        "onDenied": "RedactAll"
      }
    ],
    "policies": [
      {
        "policyId": "uuid",
        "policyType": "CATEGORY",
        "category": {
          "categoryId": "uuid",
          "categoryName": "PII"
        }
      }
    ]
  }
]

GET /api/v1/governance/purposes/\{purposeName}

Get detailed information about a specific purpose, including regulations and policies.

Response 200

{
  "purposeId": "uuid",
  "purposeName": "marketing_emails",
  "description": "Send promotional emails",
  "regulations": [...],
  "policies": [...]
}

POST /api/v1/governance/purposes

Register a new purpose. If the purpose name already exists, it is updated (upsert).

Request Body

{
  "purposeName": "marketing_emails",
  "description": "Send promotional emails to users"
}

Response 200

{
  "message": "Purpose registered"
}

DELETE /api/v1/governance/purposes/\{purposeName}

Remove a purpose and all of its associated policies and regulation links.

Response 200

{
  "message": "Purpose removed"
}

POST /api/v1/governance/purposes/policies

Add a policy to a purpose. Policies can target either a category (all fields in that category) or a specific entity/field combination.

Request Body — Category Policy

{
  "purposeName": "marketing_emails",
  "policyType": "CATEGORY",
  "categoryName": "PII"
}

Request Body — Field Policy

{
  "purposeName": "marketing_emails",
  "policyType": "FIELD",
  "entityName": "users",
  "fieldName": "email"
}

Response 200

{
  "message": "Policy added"
}

DELETE /api/v1/governance/purposes/policies

Remove a policy from a purpose by its policy ID.

Request Body

{
  "purposeName": "marketing_emails",
  "policyId": "uuid"
}

Response 200

{
  "message": "Policy removed"
}

POST /api/v1/governance/purposes/regulations

Link a purpose to a regulation, specifying the lawful basis and the data transforms to apply when consent is granted or denied.

Request Body

{
  "purposeName": "marketing_emails",
  "regulationName": "GDPR",
  "lawfulBasis": "consent",
  "onGranted": "Plaintext",
  "onDenied": "RedactAll"
}

Response 200

{
  "message": "Purpose linked to regulation"
}

DELETE /api/v1/governance/purposes/\{purposeName}/regulations/\{regulationName}

Unlink a purpose from a regulation.

Response 200

{
  "message": "Purpose unlinked from regulation"
}
