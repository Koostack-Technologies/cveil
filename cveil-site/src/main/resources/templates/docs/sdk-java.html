Java SDK

A full-featured client for Cveil with WASM-powered local consent evaluation and field masking — no network round-trips needed for masking decisions.

Note: Requires Java 21 or later.

Installation

Available on Maven Central (Sonatype).

Maven

<dependency>
  <groupId>com.koostack.cveil</groupId>
  <artifactId>cveil-sdk-java</artifactId>
  <version>0.1.0</version>
</dependency>

Gradle (Kotlin DSL)

implementation("com.koostack.cveil:cveil-sdk-java:0.1.0")

Client Initialization

import com.koostack.cveil.sdk.CveilClient;
import com.koostack.cveil.sdk.CveilClientOptions;
import com.koostack.cveil.sdk.CveilConfig;

CveilConfig config = new CveilConfig(
    "https://api.cveil.dev",       // apiBaseUrl
    "cveil_your_api_key",          // apiToken
    "EU",                          // defaultJurisdiction
    "conservativeMask",            // staleMode: "apiFallback" or "conservativeMask"
    60000L,                        // disconnectThresholdMs (default 60s)
    10000,                         // decisionCacheMaxSize (default 10000)
    300000L,                       // decisionCacheTtlMs (default 5min)
    500                            // dedupWindowSize (default 500)
);

CveilClient client = CveilClient.create(
    new CveilClientOptions(config, null, true, 100)
);

Configuration Reference

Field Type Default Description
apiBaseUrl String required Cveil API base URL
apiToken String required API token (must start with cveil_)
defaultJurisdiction String required Default jurisdiction (e.g., EU)
staleMode String conservativeMask Behavior when SSE disconnects: apiFallback (fetch from API) or conservativeMask (deny all)
disconnectThresholdMs Long 60000 Time before connection is considered stale
decisionCacheMaxSize Integer 10000 Max cached consent decisions (LRU eviction)
decisionCacheTtlMs Long 300000 Decision cache TTL
dedupWindowSize Integer 500 SSE event deduplication window

Data Masking (Core Feature)

Mask JSON objects based on consent decisions. Masking is evaluated locally via WASM — no network round-trip required.

// Mask a JSON object based on consent
Map<String, Object> userData = Map.of(
    "email", "alice@acme.com",
    "phone", "555-867-5309",
    "ssn", "412-55-6789"
);

MaskResult result = client.mask("user-123", "users", userData, "marketing_emails");
// result.data() → { "email": "****@acme.com", "phone": "***", "ssn": "***" }
// result.needsFetch() → fields that need API lookup (cache miss)
// Mask with jurisdiction override
MaskResult euResult = client.maskWithJurisdiction(
    "user-123", "users", userData, "marketing_emails", "EU"
);
// Batch masking
List<Map<String, Object>> records = List.of(userData1, userData2, userData3);
List<MaskResult> results = client.maskBatch("user-123", "users", records, "marketing_emails");

Consent Evaluation

Evaluate consent for specific fields without performing masking.

// Evaluate consent without masking
EvaluateResult eval = client.evaluate(
    "user-123", "users",
    List.of("email", "phone", "ssn"),
    "marketing_emails"
);
// Returns per-field: { field, maskingType, consentAction, needsFetch }

Consent Operations

Grant & Revoke

// Grant consent
client.grant(new GrantRequest("user-123",
    new ConsentScope(null, null, "PII", "marketing_emails", null, null),
    Instant.parse("2027-01-01T00:00:00Z")));

// Revoke consent
client.revoke(new RevokeRequest("user-123",
    new ConsentScope(null, null, "PII", "marketing_emails", null, null)));

Batch Operations

// Batch grant
client.grantAll(new BatchGrantRequest("user-123", List.of(
    new BatchConsentEntry(
        new ConsentScope(null, null, "PII", "marketing_emails", null, null),
        Instant.parse("2027-01-01T00:00:00Z")
    )
)));

Evaluate Consent

// Evaluate
ConsentResponse response = client.evaluateConsent("user-123",
    new EvaluateConsentRequest(List.of(
        new ConsentScope(null, null, "PII", "marketing_emails", null, null)
    )));

Subject Management

client.registerSubject(new RegisterSubjectRequest("user-123", "Alice's account"));
SubjectView subject = client.getSubject("user-123");
List<SubjectView> subjects = client.listSubjects();
client.updateSubject("user-123", new UpdateSubjectRequest("Updated description"));
client.removeSubject("user-123");

Governance & Catalogue

Purposes

client.registerPurpose(new RegisterPurposeRequest("marketing_emails", "Promotional emails"));
client.addPurposePolicy(new AddPurposePolicyRequest("marketing_emails", "CATEGORY", "PII", null, null));

Regulations

client.registerRegulation(new RegisterRegulationRequest("GDPR", "EU General Data Protection Regulation"));

Fields

client.registerField(new RegisterFieldRequest("users", "email", "User email"));
client.assignFieldToCategory(new AssignFieldCategoryRequest("users", "email", "PII"));

DSAR Compliance

GDPR Articles 15 (access), 17 (erasure), and 20 (portability) supported out of the box.

// Export (GDPR Article 20)
SubjectDataExport export = client.exportSubjectData("user-123");

// Erasure (GDPR Article 17)
DsarDeletionReceipt receipt = client.deleteSubjectData("user-123");
// receipt: { subjectId, requestId, ledgerEntriesRevoked, cachedKeysDeleted, status, completedAt }

// Irreversible key destruction
client.shredDsarKey("user-123");
Warning: shredDsarKey is irreversible. Once called, the subject's encryption key is permanently destroyed and their data can never be decrypted.

SDK Lifecycle

SdkStatus status = client.status();
// { initialized, connectionState, graphNodes, cachedDecisions }

client.shutdown(); // or client.close()

Architecture

The Java SDK follows a layered architecture for maximum portability:

Java Facade → Type-safe API with Java collections and records
Rust WASM Core → Consent evaluation, masking, and graph logic compiled to WebAssembly
Chicory Runtime → Pure Java WASM execution — no JNI, no native code
Note: Because the WASM core runs inside the JVM via Chicory, there are no platform-specific native dependencies. The SDK works on any OS that supports Java 21+.
