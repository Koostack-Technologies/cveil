Catalogue API

Manage the data inventory — entities (data sources), fields (sensitive columns), and categories (data classifications) that consent policies reference.

Authentication: Bearer token with appropriate permissions.

The Catalogue API defines what data your system holds and how it is classified. Three resource types work together:

  • Entities — data sources such as database tables or API resources (e.g. users).
  • Fields — individual sensitive columns within an entity (e.g. email, phone).
  • Categories — classification labels applied to fields (e.g. PII, Financial).

Governance policies can target either a specific field or an entire category, so a well-organized catalogue is the foundation for accurate consent enforcement.

Endpoint Summary

Fields

Method Endpoint Description
GET /api/v1/catalogue/fields List all registered fields
POST /api/v1/catalogue/fields Register a sensitive field (upsert)
DELETE /api/v1/catalogue/fields/\{entityName}/\{fieldName} Remove a field
POST /api/v1/catalogue/fields/categories Assign a category to a field
DELETE /api/v1/catalogue/fields/\{entityName}/\{fieldName}/categories/\{categoryName} Unassign category from field

Entities

Method Endpoint Description
GET /api/v1/catalogue/entities List all entities
GET /api/v1/catalogue/entities/\{entityName} Get entity details
GET /api/v1/catalogue/entities/\{entityName}/fields Get all fields for entity
POST /api/v1/catalogue/entities Register entity (upsert)
PUT /api/v1/catalogue/entities/\{entityName} Update entity
DELETE /api/v1/catalogue/entities/\{entityName} Remove entity

Categories

Method Endpoint Description
GET /api/v1/catalogue/categories List all categories
GET /api/v1/catalogue/categories/\{categoryName} Get category details
POST /api/v1/catalogue/categories Register category (upsert)
PUT /api/v1/catalogue/categories/\{categoryName} Update category
DELETE /api/v1/catalogue/categories/\{categoryName} Remove category

Field Endpoints

GET /api/v1/catalogue/fields

List all registered fields across all entities, including their associated categories.

Response 200

[
  {
    "fieldId": "uuid",
    "fieldName": "email",
    "description": "User email address",
    "entity": {
      "entityId": "uuid",
      "entityName": "users"
    },
    "categories": [
      {
        "categoryId": "uuid",
        "categoryName": "PII"
      }
    ]
  }
]

POST /api/v1/catalogue/fields

Register a sensitive field. If the entity/field combination already exists, it is updated (upsert).

Request Body

{
  "entityName": "users",
  "fieldName": "email",
  "description": "User email address"
}

Response 200

{
  "message": "Field registered"
}

DELETE /api/v1/catalogue/fields/\{entityName}/\{fieldName}

Remove a field registration. Any category assignments for this field are also removed.

Response 200

{
  "message": "Field removed"
}

POST /api/v1/catalogue/fields/categories

Assign a category to a field. This allows governance policies targeting that category to cover the field.

Request Body

{
  "entityName": "users",
  "fieldName": "email",
  "categoryName": "PII"
}

Response 200

{
  "message": "Category assigned to field"
}

DELETE /api/v1/catalogue/fields/\{entityName}/\{fieldName}/categories/\{categoryName}

Unassign a category from a field.

Response 200

{
  "message": "Category unassigned from field"
}

Entity Endpoints

GET /api/v1/catalogue/entities

List all registered entities.

Response 200

[
  {
    "entityId": "uuid",
    "entityName": "users",
    "description": "User accounts table"
  }
]

GET /api/v1/catalogue/entities/\{entityName}

Get detailed information about a specific entity, including its description.

Response 200

{
  "entityId": "uuid",
  "entityName": "users",
  "description": "User accounts table"
}

GET /api/v1/catalogue/entities/\{entityName}/fields

Get all fields registered under a specific entity.

Response 200

[
  {
    "fieldId": "uuid",
    "fieldName": "email",
    "description": "User email address",
    "categories": [
      {
        "categoryId": "uuid",
        "categoryName": "PII"
      }
    ]
  }
]

POST /api/v1/catalogue/entities

Register a new entity. If the entity name already exists, it is updated (upsert).

Request Body

{
  "entityName": "users",
  "description": "User accounts table"
}

Response 200

{
  "message": "Entity registered"
}

PUT /api/v1/catalogue/entities/\{entityName}

Update an existing entity's description.

Request Body

{
  "description": "Updated description"
}

Response 200

{
  "message": "Entity updated"
}

DELETE /api/v1/catalogue/entities/\{entityName}

Remove an entity and all of its associated field registrations.

Response 200

{
  "message": "Entity removed"
}
