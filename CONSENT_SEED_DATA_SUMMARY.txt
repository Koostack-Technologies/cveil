DERIVATION LOGIC: Given Jurisdiction IDs
═══════════════════════════════════════════════════════════════════════════════════

1. REGULATIONS from Jurisdiction:
   US_FEDERAL → [HIPAA, COPPA, FERPA, GLBA, FCRA, TCPA, CAN_SPAM, ECPA]
   CALIFORNIA → [CCPA]
   VIRGINIA → [VCDPA]
   COLORADO → [CPA]
   ... (1:1 mapping for each state)

2. PURPOSES from Regulations:
   Apply seedPurposeRegulationLinks() mapping
   Filter by regulations from step 1
   Example: CCPA → [SERVICE_DELIVERY, MARKETING, ANALYTICS (strict), PERSONALIZATION, ...]

3. CATEGORIES from Purposes:
   Look up seedPurposeCategoryPolicies()
   Collect all categories referenced
   Example: MARKETING → [PII, BEHAVIORAL, GEOLOCATION, COMMUNICATIONS]

4. FIELDS: Seed all ~30 default fields (jurisdiction-independent in current design)

5. FIELD-CATEGORY ASSIGNMENTS: Seed all ~50 default assignments (jurisdiction-independent)

SPECIAL NOTES
═══════════════════════════════════════════════════════════════════════════════════

• NO "template," "preset," or "industry" concept exists in the codebase
• The hardcoded seed is the ONLY governance initialization mechanism
• All commands are dispatched through JooqConsentAdminCommandService.dispatch()
• All commands trigger events → projections (async outbox → Redis → SQL/cache)
• All dispatch calls wrapped in dispatchSafe() — duplicates caught and logged as warnings
• MODPA and IowaCDPA have distinct patterns from standard state CPLs
• CCPA has special override for ANALYTICS (Consent vs. Legitimate Interest)

For parameterized seeding:
  1. Extract hardcoded lists to configurable data structures (JSON/YAML/DB)
  2. Create parametric seed actuator accepting template ID
  3. Map template fields to command actuators dynamically
  4. Maintain jurisdiction-regulation derivation mapping
